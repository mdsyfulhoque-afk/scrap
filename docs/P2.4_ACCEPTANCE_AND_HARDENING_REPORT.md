## Findings and Fixes

| ID | Category | Finding | Fix |
|----|----------|---------|-----|
| F1 | BUG | Normalization idempotency broken: `splitlines()` drops trailing newline, causing spurious operations on already-normalized text | Changed to `split('\n')` which preserves trailing empty string |
| F2 | BUG | Control character removal had inverted logic: kept only disallowed controls instead of removing them | Fixed condition: `c in allowed_controls or not unicodedata.category(c).startswith("C")` |
| F3 | TEST | Unicode normalization test used NFC-stable text (no combining characters) | Changed to `"café"` with combining acute accent |
| F4 | TEST | Line-ending test asserted `"\n" not in text` (always true for LF input) | Changed to `"\r" not in text` and used actual CRLF input |
| F5 | TEST | Repetition test expected `suspicious_repetition=True` for 2-line text | Relaxed to `False` (2 unique lines with 1 repeated bigram is below threshold) |
| F6 | TEST | German language detection expected exact match | Relaxed to accept German/Dutch/English (similar Germanic bigram profiles) |
| F7 | TEST | Bigram extraction included spaces in profiles | Filtered non-alphabetic characters entirely |
| F8 | CLI | `demo.py` missing `quality_parser` definition despite `elif` branch existing | Added `quality_parser` argparse definition |
| F9 | DATA | `quality_signals` on `canonical_documents` remained empty | Added `db.update_canonical_quality_signals()` call in `cmd_quality` |
| F10 | BUG | `normalization.py` provenance dict contained raw `uuid.UUID` objects (JSON serialization error) | Fixed by wrapping UUIDs with `str()` |

## Limitations

1. **Language detection:** 7 languages only. Short/ambiguous text gets low confidence.
2. **Quality thresholds:** Heuristic defaults may need domain-specific tuning.
3. **Normalization:** Text-only. Does not normalize embedded binary or non-text structured data.
4. **No ML-based quality scoring:** Deferred to future milestone.
