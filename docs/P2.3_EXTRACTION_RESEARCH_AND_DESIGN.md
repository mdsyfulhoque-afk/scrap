# P2.3 — Canonical Representation & Extraction
## Research and Design Document

## 1. Purpose

P2.3 converts characterized artifacts into deterministic, versioned canonical representations that preserve structured information for downstream Phase 2 stages:

- P2.4 Quality & Analytics
- P2.5 Deduplication
- P2.6 Dataset Specification
- P2.7 Dataset Builder
- P2.8 Validation
- P2.9 Export

## 2. Architecture

```
Artifact (Phase 1)
    ↓
ArtifactCharacterization (P2.2)
    ↓
Extractor (P2.3)
    ↓
CanonicalDocument (P2.3)
    ↓
Downstream stages (P2.4+)
```

The extraction layer respects P2.2 characterization output:

- `detected_format`
- `format_confidence`
- `structural_type`
- `document_type_candidates`
- `schema_summary`
- `extraction_suitability`
- `warnings`
- `metadata_availability`

## 3. Supported Formats

| Format | Status | Structured Preservation |
|--------|--------|------------------------|
| HTML | Supported | Title, headings, links, text |
| JSON | Supported | Full parsed object/array |
| XML | Supported | Tree structure, attributes, text |
| CSV | Supported | Headers, rows, columns |
| Markdown | Supported | Headings, code blocks, text |
| Plain text | Supported | Normalized text, line stats |

## 4. Canonical Document Model

**Database table:** `canonical_documents`

**Model:** `CanonicalDocument`

Fields:
- `artifact_id` — Unique link to Phase 1 artifact
- `processing_job_id` — Link to processing job
- `source_url` — Original resource URL
- `source_mime_type` — Declared MIME type
- `detected_format` — P2.2 detected format
- `extraction_status` — pending/running/completed/failed/unsupported/partial
- `canonical_text` — Deterministic textual representation
- `structured_data` — JSONB preserved structure (when applicable)
- `metadata` — Extraction metadata (JSONB)
- `structure` — Format-specific structure summary (JSONB)
- `extraction_method` — Method identifier
- `extraction_version` — Version for reproducibility
- `warnings` — Non-fatal issues (JSONB)
- `errors` — Fatal issues (JSONB)
- `original_checksum` — SHA-256 of raw artifact
- `canonical_checksum` — SHA-256 of canonical text
- `provenance` — Full provenance chain (JSONB)
- `created_at` / `updated_at` — Timestamps

## 5. Extraction Strategy

Format-specific extractors dispatch based on `detected_format`:

### HTML
- Uses stdlib `html.parser.HTMLParser`
- Extracts: title, readable text, links, headings
- Removes: script, style, noscript, nav, footer
- Preserves: document structure metadata
- Output: canonical text + structured links/headings

### JSON
- Uses stdlib `json`
- Preserves: full parsed object/array structure
- Canonical text: `json.dumps(data, sort_keys=True, ensure_ascii=False, indent=2)`
- Deterministic: field ordering is stable via `sort_keys=True`

### XML
- Uses stdlib `xml.etree.ElementTree`
- Preserves: root tag, hierarchy, attributes, text content
- Limits: tree depth capped at 5 levels, 50 children per node
- Canonical text: concatenated text content

### CSV
- Uses stdlib `csv`
- Preserves: headers, rows, column count, row count
- Limits: 1000 rows for structured data
- Canonical text: tab-separated headers + rows

### Markdown
- Custom regex-based parser
- Preserves: headings, code blocks (with language), text
- Canonical text: original markdown preserved as-is

### Plain Text
- Normalizes line endings to `\n`
- Strips trailing whitespace per line
- Preserves: content, line count, character count

## 6. Error Model

Explicit error categories:

| Category | Meaning |
|----------|---------|
| `unsupported_format` | No extractor for detected format |
| `unknown_format` | Characterization produced no format |
| `corrupted_format` | Parse error (invalid JSON, XML, CSV) |
| `encoding_error` | Cannot decode bytes |
| `empty_content` | Zero-length content |
| `parser_error` | Parser-level failure |
| `extraction_error` | Unexpected extraction failure |

## 7. Provenance

Preserves full chain:

resource → fetch → artifact → characterization → extraction → canonical document

Stored in `canonical_documents.provenance` JSONB:

```json
{
  "artifact_id": "...",
  "processing_job_id": "...",
  "fetch_id": "...",
  "resource_id": "...",
  "resource_url": "...",
  "bucket_name": "...",
  "object_key": "..."
}
```

## 8. Reproducibility

- Extraction is versioned (`extraction_version`)
- Deterministic by design (no randomness, stable serialization)
- Same input + same version = same output
- Checksums verify integrity: `original_checksum` → `canonical_checksum`

## 9. Processing Job Integration

Uses existing `processing_jobs` table:

- Job created: `extract-{artifact_id}`
- Status: `pending` → `running` → `completed`/`failed`
- No separate job system

## 10. CLI

```
python -m data_fetcher.demo phase2 extract <artifact-id>
```

Output includes:
- Artifact info
- Detected format
- Extraction method and status
- Canonical text preview with checksum
- Structured data preview
- Structure summary
- Provenance
- Warnings/errors
- Storage confirmation (canonical document ID)

## 11. Limitations

1. **HTML extraction is basic:** Uses stdlib parser only. No advanced boilerplate removal or readability scoring.
2. **XML depth limited:** Tree serialization capped at 5 levels, 50 children.
3. **CSV row limit:** Structured data limited to 1000 rows.
4. **No PDF/DOCX/XLSX:** Not implemented in P2.3.
5. **Markdown parsing is heuristic:** Not a full CommonMark parser.

## 12. Dependencies

**New external dependencies:** None (stdlib only)

**Stdlib modules used:**
- `html.parser` — HTML parsing
- `json` — JSON parsing and canonical serialization
- `xml.etree.ElementTree` — XML parsing
- `csv` — CSV parsing
- `re` — Markdown pattern matching
- `hashlib` — Checksums
- `io.StringIO` — CSV text buffer

## 13. Security Considerations

- No code execution during extraction
- No network access during extraction
- XML external entity (XXE) protection: stdlib `ElementTree` does not resolve external entities by default
- Size limits enforced: `max_canonical_text_bytes` (default 10MB)
- Input is raw bytes from trusted object storage

## 14. Resource Limits

- Memory: bounded by preview size (64KB) + structured data caps
- CPU: stdlib parsing, no ML
- No GPU required
- Deterministic and streaming-friendly
