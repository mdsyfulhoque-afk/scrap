## 1. Definitions

### Exact Duplicate (Raw)
Two artifacts are **raw exact duplicates** when their `original_checksum` (SHA-256 of the raw MinIO payload) is identical. This means the byte-for-byte content stored in MinIO is the same.

### Exact Duplicate (Normalized)
Two documents are **normalized exact duplicates** when their `normalized_checksum` (SHA-256 of the normalized canonical text) is identical, but their `original_checksum` differs. This captures cases where different raw artifacts normalize to the same content (e.g., different HTML formatting, different whitespace, different Unicode representations).

### Near Duplicate
Two documents are **near duplicates** when their normalized text is substantially similar but not identical. Similarity is measured using character trigram Jaccard similarity. A configurable threshold determines the cutoff.

### Duplicate Group
A **duplicate group** is a set of documents that are duplicates of each other. Groups are formed via transitive closure: if A≈B and B≈C, then A, B, and C belong to the same group.

### No Duplicate Detected
Documents that do not match any other document under the configured thresholds are marked as unique.

### Duplicate Detection Unavailable
Documents without normalized text (failed extraction, failed normalization, or unavailable normalized document) cannot participate in duplicate detection and are marked as unavailable.

---

## 2. Content Compared

P2.5 operates primarily on **normalized content** from `normalized_documents.normalized_text`.

- **Raw exact duplicates:** compared at the `artifacts.checksum_sha256` level
- **Normalized exact duplicates:** compared at the `normalized_documents.normalized_checksum` level
- **Near duplicates:** compared at the `normalized_documents.normalized_text` level using character trigrams

Structured data (`structured_data`) is NOT compared in P2.5. It may be incorporated in future phases.

| Trigram hashing | SHA-256 (for deterministic min-hash sketch) | Computed at runtime |

## 4. Duplicate Group Formation

### Grouping Rules
1. **Raw exact groups:** All artifacts sharing the same `checksum_sha256` form a group with method `raw_exact`.
2. **Normalized exact groups:** All normalized documents sharing the same `normalized_checksum` form a group with method `normalized_exact`.
3. **Near-duplicate groups:** Documents with trigram Jaccard similarity ≥ threshold form groups with method `near_duplicate`.
4. **Transitive closure:** Near-duplicate groups use union-find to ensure transitive grouping (A≈B, B≈C → A,B,C in same group).
5. **Priority:** If a document belongs to both an exact group and a near-duplicate group, the exact group takes precedence. The document is excluded from near-duplicate grouping.

### Transitive Behavior
- Near-duplicate grouping uses union-find (disjoint-set) data structure.
- The union-find is seeded deterministically by sorted document IDs.
- Group membership is reproducible given identical input state, algorithm version, and configuration.

## 5. Representative Selection

### Selection Priority (deterministic, ordered):
1. **Successful normalization:** Prefer documents with `normalized_documents.normalized_text` present and non-empty.
2. **Higher quality score:** Prefer documents with higher `completeness_signals.character_count` (proxy for content richness).
3. **Fewer warnings:** Prefer documents with fewer total warnings (extraction + normalization warnings).
4. **Stable tie-breaker:** Prefer lexicographically smallest `normalized_documents.id` (UUID string comparison).

### Selection Basis Storage
The reason for representative selection is stored in `duplicate_memberships.selection_basis` as a human-readable string (e.g., "highest_quality_fewest_warnings_stable_id").

Every duplicate decision preserves:
- `original artifact_id`
- `canonical_document_id`
- `normalized_document_id`
- `source_url` (from artifact)
- `comparison_method` (raw_exact, normalized_exact, near_duplicate)
- `algorithm_version` (e.g., "trigram-jaccard-1.0.0")
- `algorithm_config` (threshold, shingle size, etc.)
- `similarity_score` (where applicable)
- `duplicate_group_id`
- `is_representative` flag
- `selection_basis` (for representatives)
- `created_at` / `updated_at` timestamps
- `warnings` / `errors` lists
- Full provenance chain in JSONB

- "Exclude all raw exact duplicates"

## 8. Algorithm Details

### Raw Exact Detection
- Scan all artifacts, group by `checksum_sha256`
- Groups with size > 1 are raw exact duplicate groups
- Deterministic: SHA-256 is deterministic, grouping by sorted checksum is deterministic

### Normalized Exact Detection
- Scan all normalized documents, group by `normalized_checksum`
- Groups with size > 1 are normalized exact duplicate groups
- Exclude documents already in raw exact groups (to avoid double-counting)
- Deterministic: SHA-256 is deterministic

### Near-Duplicate Detection
1. **Shingle extraction:** Extract character trigrams (3-grams) from `normalized_text`
2. **Min-hash sketch:** Compute a deterministic min-hash sketch of size 128 using SHA-256 hashed trigrams
   - Hash each trigram with SHA-256
   - Sort the hashes
   - Take the first 128 smallest hashes as the sketch
   - This is deterministic for identical input
3. **Candidate generation:** Use banding on the min-hash sketch to generate candidate pairs
   - Split the 128-element sketch into 16 bands of 8 elements each
   - Documents sharing any band are candidates for detailed comparison
   - This reduces comparisons from O(n²) to near-linear for large datasets
4. **Similarity calculation:** For candidate pairs, compute exact Jaccard similarity of trigram sets
   - Jaccard = |A ∩ B| / |A ∪ B|
5. **Thresholding:** Documents with Jaccard ≥ `similarity_threshold` (default 0.85) are considered near duplicates
6. **Transitive closure:** Union-find merges connected components

### Resource Limits
- Trigram extraction operates on `normalized_text` only, capped at 10MB per document (existing limit)
- Min-hash sketch size: 128 elements (fixed)
- Band count: 16 bands of 8 elements each
- Memory: O(n * 128) for sketches, O(n) for union-find
- CPU: O(total_chars) for trigram extraction, O(candidates) for Jaccard computation
- No GPU required
- Suitable for datasets up to ~100,000 documents on 16GB RAM

### Deterministic vs Heuristic
| Aspect | Deterministic | Heuristic |
|--------|--------------|-----------|
| Raw exact detection | Yes | No |
| Normalized exact detection | Yes | No |
| Trigram extraction | Yes | No |
| Min-hash sketch | Yes | No |
| Banding | Yes | No |
| Jaccard similarity | Yes | No |
| Threshold selection | No | Yes (configurable, default 0.85) |
| Representative selection | Yes | No (priority-ordered but deterministic) |

## 9. Database Schema

### Table: `duplicate_groups`
```sql
CREATE TABLE duplicate_groups (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    duplicate_method TEXT NOT NULL,  -- raw_exact, normalized_exact, near_duplicate
    algorithm_version TEXT NOT NULL DEFAULT 'trigram-jaccard-1.0.0',
    algorithm_config JSONB NOT NULL DEFAULT '{}'::jsonb,
    representative_normalized_document_id UUID,  -- FK to normalized_documents
    representative_canonical_document_id UUID,   -- FK to canonical_documents
    group_size INT NOT NULL DEFAULT 0,
    similarity_stats JSONB NOT NULL DEFAULT '{}'::jsonb,
    warnings JSONB NOT NULL DEFAULT '[]'::jsonb,
    errors JSONB NOT NULL DEFAULT '[]'::jsonb,
    provenance JSONB NOT NULL DEFAULT '{}'::jsonb,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

### Table: `duplicate_memberships`
```sql
CREATE TABLE duplicate_memberships (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    group_id UUID NOT NULL REFERENCES duplicate_groups(id) ON DELETE CASCADE,
    normalized_document_id UUID REFERENCES normalized_documents(id) ON DELETE CASCADE,
    canonical_document_id UUID REFERENCES canonical_documents(id) ON DELETE CASCADE,
    artifact_id UUID REFERENCES artifacts(id) ON DELETE CASCADE,
    comparison_method TEXT NOT NULL,
    similarity_score FLOAT,
    is_representative BOOLEAN NOT NULL DEFAULT false,
    selection_basis TEXT,
    warnings JSONB NOT NULL DEFAULT '[]'::jsonb,
    errors JSONB NOT NULL DEFAULT '[]'::jsonb,
    provenance JSONB NOT NULL DEFAULT '{}'::jsonb,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    CHECK (
        (normalized_document_id IS NOT NULL)::int +
        (canonical_document_id IS NOT NULL)::int +
        (artifact_id IS NOT NULL)::int
        = 1
    )
);
```

### Indexes
- `duplicate_groups`: PK on `id`, index on `duplicate_method`, index on `algorithm_version`
- `duplicate_memberships`: PK on `id`, index on `group_id`, index on `normalized_document_id`, index on `canonical_document_id`, index on `artifact_id`

### Why This Schema
- Minimal tables (2) supporting all requirements
- Proper foreign keys (no JSONB relationships)
- Check constraint ensures exactly one document reference per membership
- Unique constraint on `(group_id, normalized_document_id)` and `(group_id, canonical_document_id)` and `(group_id, artifact_id)` prevents duplicate memberships
- JSONB used only for flexible config/stats, not for relationships

## 11. CLI Commands

### `python -m data_fetcher.demo phase2 deduplicate`
Run full deduplication on all available normalized documents.

### `python -m data_fetcher.demo phase2 duplicate-group <group-id>`
Inspect a specific duplicate group.

### `python -m data_fetcher.demo phase2 duplicates --threshold <value>`
Run deduplication with custom similarity threshold.

### Output Requirements
The CLI must clearly answer:
1. How many records were analyzed?
2. How many exact duplicate groups were found?
3. How many near-duplicate groups were found?
4. Which algorithm/version was used?
5. Which similarity threshold was used?
6. Which records were selected as representatives?
7. Why was each representative selected?
8. How many records remain if one representative per group is selected?
9. Were any records skipped or unavailable?
10. Were any detection errors encountered?
