## Architecture

### Exact Duplicate Definition
Two artifacts are **raw exact duplicates** when their `artifacts.checksum_sha256` (SHA-256 of raw MinIO payload) is identical.

### Normalized Duplicate Definition
Two documents are **normalized exact duplicates** when their `normalized_documents.normalized_checksum` is identical, but their `artifacts.checksum_sha256` differs.

### Near Duplicate Definition
Two documents are **near duplicates** when their character trigram Jaccard similarity >= configurable threshold (default 0.85).

### Algorithm
- **Raw exact:** SHA-256 grouping
- **Normalized exact:** SHA-256 grouping
- **Near duplicate:** Character trigram extraction -> deterministic min-hash sketch (128 elements) -> banding (16 bands of 8) -> candidate generation -> exact Jaccard similarity -> union-find transitive closure

### Algorithm Version
`trigram-jaccard-1.0.0`

### Threshold
Default: 0.85 (configurable via CLI --threshold)

### Candidate Generation Strategy
Min-hash banding: documents sharing any band are candidates for detailed Jaccard comparison. Reduces comparisons from O(n^2) to near-linear for typical datasets.

### Complexity/Resource Considerations
- Trigram extraction: O(total_chars) per document
- Min-hash sketch: O(unique_trigrams) per document
- Banding: O(n * sketch_size / band_count)
- Jaccard comparison: O(candidates * avg_trigram_set_size)
- Memory: O(n * sketch_size) for sketches, O(n) for union-find
- CPU-only, no GPU required
- Suitable for datasets up to ~100,000 documents on 16GB RAM

## Duplicate Groups

### Grouping Rules
1. Raw exact: group by artifacts.checksum_sha256
2. Normalized exact: group by normalized_documents.normalized_checksum
3. Near duplicate: union-find transitive closure of Jaccard >= threshold pairs
4. Priority: exact groups take precedence; documents in exact groups excluded from near-duplicate detection

### Transitive Behavior
- Near-duplicate groups use union-find (disjoint-set) with union-by-rank and path compression
- Group membership is reproducible given identical input state, algorithm version, and configuration
- Deterministic sorting of members by ID ensures stable group composition

### Representative Selection Rules
1. Prefer documents with normalized text present
2. Prefer higher quality score (character_count / 1000, capped at 1.0)
3. Prefer fewer warnings
4. Stable ID tie-breaker (lexicographically smallest document_id)

### Provenance Preservation
Every duplicate decision preserves:
- Original artifact identity
- Canonical document identity
- Normalized document identity
- Source URL
- Comparison method
- Algorithm version and configuration
- Similarity score (where applicable)
- Duplicate group identity
- Representative record
- Selection basis
- Timestamps
- Warnings/errors

## Known Limitations

1. **Near-duplicate detection requires normalized text:** Documents without normalized text (failed extraction/normalization) cannot participate in near-duplicate detection.
2. **Language coverage:** Trigram-based similarity works best for alphabetic scripts. Non-Latin scripts may need different shingle sizes.
3. **Memory for large datasets:** Min-hash sketches are small (128 elements), but very large datasets (>100,000 docs) may need additional candidate-generation optimizations.
4. **No ML-based similarity:** Deterministic trigram Jaccard only. Semantic similarity requires future ML-based approach.
5. **Only 1 normalized document in current DB:** Live verification found 0 duplicate groups because only 1 document has been normalized. Full testing requires running P2.3/P2.4 on more artifacts.
